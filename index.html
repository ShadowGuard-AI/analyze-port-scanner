The Night Round

I wrote this tool to do two related jobs: scan a host's TCP ports myself, and analyze scan results another tool already produced. Either way, what comes out is a short, readable list of what is open and what deserves a second look.

The two jobs

scan probes a host with plain TCP connect attempts and reports the ports that complete a handshake, with service names. analyze reads an existing scan output file and summarizes it per host, parsing nmap normal output, nmap grepable output, and plain host:port lines. Both modes flag the ports always worth calling out by name: Telnet, FTP, SMB, RDP, VNC, and exposed database ports such as MySQL, PostgreSQL, Redis, and MongoDB. Both modes can emit JSON with --json and write to a file with --output.

--outputwrite the report to this file instead of stdout. If the output path resolves to the input file, the run refuses and exits non-zero rather than overwrite the scan it was handed.

Exit codes and stated limits

0: the run did its work. A scan that probed its ports and found nothing open says so and still exits 0, because the probing happened. 2: the run processed nothing or was refused: an unresolvable host, no ports selected, a missing input file, a scan file with no parseable results, or an --output that points at the input file.

Lines the analyze mode cannot understand are counted and reported as skipped, never guessed at.

Verified in Wave 12, as the README records it: scan on 127.0.0.1 with --ports 22,80,443 reports 3 ports probed, 0 open, exit 0; analyze on a crafted nmap-style file reproduces the example shape, 6 port rows across 3 hosts, 5 open, with Telnet, MySQL, and Redis flagged by name.
