A timetable sheet for a line with exactly two services. Scan runs on the left road, analyze on the right road.

Masthead: the line's charter

I wrote this tool to do two related jobs: scan a host's TCP ports myself, and analyze scan results another tool already produced. Either way, what comes out is a short, readable list of what is open and what deserves a second look, instead of a wall of raw scanner output.

That charter stays in the first person on this sheet, because the source's voice is part of its evidence.

The Scan Road

Scan probes a host with plain TCP connect attempts and reports the ports that complete a handshake, with service names.

hostThe hostname or IP address to scan.
--portsA comma list of ports and ranges such as 22,80,8000-8100, defaulting to a common services set.
--port-rangeOne more range to add, such as 1-1024.
--timeoutSeconds per connect attempt, default 0.6.

Timetable entry, the worked example:

python3 main.py scan 127.0.0.1 --ports 22,80,443
Scanned 127.0.0.1 (127.0.0.1): 3 ports probed, 0 open
  nothing open in the probed set

The Analyze Road

Analyze reads an existing scan output file and summarizes it per host, parsing nmap normal output, nmap grepable output, and plain host:port lines. Lines it cannot understand are counted and reported as skipped, never guessed at.

fileThe scan output file to parse.

Timetable entry, the worked example:

python3 main.py analyze scan-results.txt
Analyzed scan-results.txt: 6 port rows across 3 hosts, 5 open
192.0.2.10:
  22/tcp open ssh
  23/tcp open telnet  <- Telnet, plaintext remote shell
  80/tcp closed http
192.0.2.20:
  443/tcp open https
  3306/tcp open mysql  <- MySQL or MariaDB
192.0.2.30:
  6379/tcp open redis  <- Redis, often unauthenticated
(1 lines not understood and skipped)

Recorded result: 6 port rows across 3 hosts, 5 open, ending with 1 line not understood and skipped.

Stops Both Roads Call At

Both modes flag the ports the author always wants called out by name: Telnet, FTP, SMB, RDP, and VNC, and exposed database ports such as MySQL, PostgreSQL, Redis, and MongoDB.

Both modes can emit JSON with --json and write to a file with --output. Help is reached by python3 main.py --help or python3 main.py scan --help.

The Plow Does Not Bury Its Own Track

On the analyze road, --output carries a guard stated plainly: if the output path resolves to the input file, the run refuses and exits non zero rather than overwrite the scan it was handed.

Terminus: boarding and alighting rules

git clone https://github.com/ShadowGuard-AI/analyze-port-scanner.git
cd analyze-port-scanner

And then nothing, since the source states Python 3, standard library only, there is nothing to install. That fact is printed in its own panel here rather than apologized for.

What the Bell Means

Exit codes close the sheet. 0 means the run did its work, and a scan that found nothing open still exits 0 because the probing happened. 2 means the run processed nothing or was refused, covering an unresolvable host, no ports selected, a missing input file, a scan file with no parseable results, or an output path pointing at the input file.
